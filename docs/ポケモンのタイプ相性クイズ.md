## ざっくりとした仕様

- ポケモンチャンピオンズでは、相手の手持ち６体に対して、自分のどのポケモンが有効な確率が高いか判断したい。
- ただし、そのためにはタイプ相性を全て把握しておく必要がある。
- タイプ相性有利の理論値を出すためのトレーニングツールをWebアプリで開発したい。
- 可能であればbackendはほぼ不要、ログインも不要な作りとしたい

## ローンチ版の仕様

### コンセプト

相手の手持ち6体のタイプ構成を見て、こちらの候補ポケモン／候補タイプのうち「タイプ相性だけで見た有利度」が最も高いものを素早く判断するための、ブラウザ完結型トレーニングWebアプリ。

> [!important] ローンチ版の割り切り
> 種族値、特性、持ち物、技威力、テラスタル／メガシンカ等の個別要素は扱わない。まずは「タイプ相性の暗記と瞬間判断」に特化する。

### 想定ユーザー

- ポケモン対戦でタイプ相性を素早く判断したい人
- 相手6体を見たときに、自分の選出候補のどれがタイプ上有利か練習したい人
- ログインなしでスマホから短時間練習したい人

### MVPで提供する機能

#### 1. タイプ相性クイズ

- 1問につき、相手側の6体を表示する。
- 各相手ポケモンは「単タイプ」または「複合タイプ」で表現する。
- ユーザーは、こちら側の候補から最もタイプ相性が良いものを1つ選ぶ。
- 回答後に以下を表示する。
  - 正解／不正解
  - 各候補の有利度スコア
  - 相手6体それぞれに対する倍率内訳
  - なぜその候補が最も良いかの短い解説

#### 2. 練習モード

ローンチ時は以下の2モードに絞る。

##### A. 攻撃有利モード

「こちらの攻撃タイプが、相手6体にどれだけ通りやすいか」を問うモード。

- 問題例：相手6体のタイプ構成に対して、最も一貫する攻撃タイプを選ぶ。
- 候補はタイプ単位で出す。
- 学習目的：攻撃面の一貫性を覚える。

##### B. 候補ポケモン選択モード

「こちらの候補ポケモンのタイプ構成が、相手6体に対してどれだけ有利か」を問うモード。

- こちらの候補を3〜4体表示する。
- 各候補は名前ではなく、ローンチ版ではタイプ構成で表す。
  - 例：`みず / フェアリー`、`じめん / はがね`
- 学習目的：自分の選出候補のタイプ上の強弱を判断する。

#### 3. スコア計算

ローンチ版では、複雑な対戦シミュレーションではなく、タイプ相性だけの理論値を使う。

##### 攻撃有利スコア

各相手に対する攻撃倍率を合計する。

```text
攻撃有利スコア = 相手6体への攻撃倍率の合計
```

倍率は通常のタイプ相性を使う。

- `0倍`: 無効
- `0.25倍`: 複合タイプで二重半減
- `0.5倍`: 半減
- `1倍`: 等倍
- `2倍`: 抜群
- `4倍`: 複合タイプで二重弱点

同点の場合は、以下の順で判定する。

1. `0倍`を取られる回数が少ない
2. `0.5倍以下`を取られる回数が少ない
3. `2倍以上`を取れる回数が多い
4. それでも同点なら複数正解扱い

##### 候補ポケモン有利スコア

ローンチ版では、候補ポケモンの「攻撃面」と「防御面」を分けて表示し、総合スコアで正解を決める。

```text
総合スコア = 攻撃面スコア + 防御面スコア
```

- 攻撃面スコア：候補ポケモンのタイプ一致攻撃が、相手6体にどれだけ通るか
- 防御面スコア：相手6体のタイプ一致攻撃を、候補ポケモンがどれだけ受けやすいか

防御面は「低い被ダメ倍率ほど高評価」に変換する。

| 被ダメ倍率 | 防御評価点 |
| --- | ---: |
| 0倍 | 4 |
| 0.25倍 | 3 |
| 0.5倍 | 2 |
| 1倍 | 1 |
| 2倍 | -1 |
| 4倍 | -3 |

> [!note]
> スコアは「学習用の近似値」であり、実戦での絶対的な強さではないと明記する。

#### 4. 問題生成

- 18タイプからランダムに相手6体のタイプ構成を生成する。
- 単タイプと複合タイプを混ぜる。
- ローンチ版では実在ポケモンの名前・画像は使わない。
- 難易度を3段階に分ける。

| 難易度 | 内容 |
| --- | --- |
| Easy | 単タイプ中心。候補も分かりやすい。 |
| Normal | 単タイプと複合タイプを混在。 |
| Hard | 複合タイプ中心。同点・僅差が出やすい。 |

#### 5. 結果・学習補助

- 連続正解数を表示する。
- 直近10問の正答率を表示する。
- 苦手タイプを簡易表示する。
  - 例：`はがねへの攻撃判断でミスが多い`
- 成績はセッション中のみ保持する。
- ページを閉じたりリロードしたりしたら、一からやり直しでよい。
- ログイン、サーバー保存、ランキング、ブラウザ永続保存は作らない。

#### TypeSet

```ts
type TypeSet = {
  primary: PokemonType;
  secondary?: PokemonType;
};
```

#### QuizQuestion

```ts
type QuizQuestion = {
  id: string;
  mode: 'attack-coverage' | 'candidate-selection';
  difficulty: 'easy' | 'normal' | 'hard';
  opponents: TypeSet[]; // 6件
  choices: TypeSet[] | PokemonType[];
  correctChoiceIndexes: number[];
};
```

#### QuizResult

セッション中の状態としてメモリ上だけで保持する。永続化はしない。

```ts
type QuizResult = {
  questionId: string;
  selectedChoiceIndex: number | null;
  correct: boolean;
  answeredAt: string;
  mistakeTypes: PokemonType[];
};
```

### 技術方針

- フロントエンドのみで実装する。
- ログインなし。
- バックエンドなし。
- 永続保存なし。回答履歴・成績はアプリ起動中のメモリ状態だけで扱う。
- デプロイ先は静的ホスティングでよい。
  - Vercel
  - Netlify
  - GitHub Pages
- 実装候補：
  - Next.js static export
  - Vite + React
  - SvelteKit static

ローンチ優先なら、構成は `Vite + React + TypeScript` が最小でよい。

### ClaudeにUI/UXデザインを任せるときの注意事項

#### 依頼時に必ず伝える前提

- ローンチ版は「タイプ相性の瞬間判断を鍛える」ことが目的。見た目の豪華さより、問題を解くテンポを優先する。
- スマホ利用を主目的にする。PCでも使えるが、まずは片手操作しやすいモバイルUIを基準にする。
- バックエンド、ログイン、永続保存はない。セッション中だけの軽いクイズアプリとして設計する。
- 公式素材は使わない。ポケモン名・公式画像・公式アイコンに依存しない、タイプ色とテキスト中心のUIにする。
- 非公式ファンメイドツールである注記を自然に表示できるデザインにする。

#### UXで重視すること

- 1問あたりの操作数を少なくする。
  - モード選択後は、回答 → 解説確認 → 次の問題、の流れを最短にする。
- 相手6体のタイプ構成を一目で比較できることを優先する。
- 回答候補は押しやすい大きさにする。
- 正解／不正解だけでなく、「なぜそうなるか」がすぐ分かる倍率表を出す。
- 解説は長文にしすぎない。詳細よりも、次の判断に使える気づきを優先する。
- 連続正解数や直近正答率は、主役にしすぎず、モチベーション補助として表示する。

#### UIで避けたいこと

- 公式ゲーム画面に似せすぎない。
- 派手なアニメーションで回答テンポを落とさない。
- タイプ相性表を常時大きく表示して、クイズ性を弱めない。
- 色だけでタイプや正誤を判別させない。必ずテキスト・アイコン風ラベル・倍率表記も併用する。
- 初回から設定項目を増やしすぎない。ローンチ版では「モード」「難易度」程度でよい。

#### アクセシビリティ

- タイプごとの色は使ってよいが、色覚差に配慮してコントラストを高める。
- すべてのタイプラベルに日本語名を表示する。
- ボタンはスマホで押しやすいサイズにする。
- 正解は緑、不正解は赤だけに頼らず、`正解` / `不正解` のテキストも表示する。
- 倍率は `2x` だけでなく、`ばつぐん 2x` のように意味も添える。

### 法務・公開時の注意

- 公式画像、公式アイコン、ゲーム内スクリーンショットは使わない。
- 実在ポケモン名を大量に収録する機能はローンチ版では避ける。
- アプリ内に「非公式ファンメイドツールであり、公式とは関係ありません」と明記する。
- タイトルは公開時に `タイプ相性クイズ` や `18タイプ相性トレーナー` のような一般名に寄せる。
